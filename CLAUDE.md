# MorseWave — контекст для Claude Code

Тренажёр азбуки Морзе. PHP (без фреймворка) + MySQL (PDO) + ванильный JS.
Живёт на https://morse.r9old.ru, репозиторий: https://github.com/loloka/morsewave

Полное описание проекта и архитектура — в [README.md](README.md) (русский,
основной — так видят GitHub-посетители по умолчанию) / [README.en.md](README.en.md)
(английский, синхронная копия), запуск/деплой/миграции/администрирование —
в [DEPLOY.md](DEPLOY.md),
история изменений — в [CHANGELOG.md](CHANGELOG.md).
Этот файл — только то, что нужно знать *перед тем как писать код*.

Интерфейс сайта двуязычный (русский/английский, v2.49) — см. правило про
`lang/*.php` и `t()` ниже. README и этот файл (документация для разработки)
двуязычны отдельно и независимо от рантайм-интерфейса сайта.

## Локальный запуск

```bash
docker compose up -d --build
```
Сайт: http://localhost:8080 · phpMyAdmin: http://localhost:8081 (root / morsewave_root)

При первом запуске MySQL-контейнер автоматически накатывает
`database/schema.sql` — полную актуальную схему с сидами (см.
`docker-compose.yml`, `docker-entrypoint-initdb.d`). Это происходит
**только один раз**, на пустом volume. На уже существующей базе изменения
схемы применяются вручную через phpMyAdmin или `docker compose exec db mysql ...`.

## Обязательные правила (не откатывать без явной просьбы пользователя)

- **XP — всегда целые числа.** `Progress.addXp()` в `assets/js/progress.js`
  округляет через `Math.round`. Если формула даёт дробный множитель —
  округляй результат ДО вызова `addXp`, не после. Повторное сложение
  дробных чисел в JS даёт ошибку плавающей точки (`592.5000000000002`) —
  это уже было багом, не повторяй его.
- **Один `AudioContext` на весь сайт.** Никогда не создавай
  `new AudioContext()` напрямую — используй `getSharedAudioContext()` из
  `assets/js/audio.js`. Причина: у браузеров есть лимит на число
  одновременно живых контекстов; создание нового на каждое воспроизведение
  рано или поздно приводило к зависанию тренировки без звука и без реакции
  на клики (было багом, чинили специально). Все `await audio.play(...)`
  оборачивай в `try/catch/finally`, сбрасывающий флаг занятости
  (`isPlaying`/`recBusy`) в `finally`.
- **Кнопка «Остановить» обязана останавливать по-настоящему** (v2.31). Одного
  флага `running = false` мало: уже идущий `await audio.play()` доигрывает
  символ, а отложенный `setTimeout` на следующий раунд всё равно срабатывает —
  при повторном «Начать» получаются параллельные цепочки и звук накладывается
  сам на себя (был реальный баг). Рабочий шаблон — в `learn.js`/`groups.js`:
  токен запуска (`recSessionId`/`abbrevSessionId`), который старая цепочка
  сверяет в `finally` и в `onSymbol`, плюс общая функция остановки
  (`haltRecognize()`/`haltAbbrev()`), гасящая звук через `MorseAudio.stop()`,
  снимающая `clearTimeout` и чистящая лампу с сигнальной линией. Её же надо
  звать при уходе со вкладки.
- **wpm-контролы — везде `<input type="range">` с шагом 1**, не `<select>`
  с пресетами. Осознанное решение пользователя.
- **XP не должен фармиться** повторением тривиального действия. При
  добавлении нового источника XP — закладывай защиту (см. `learn.js`: XP
  только пока символ/условие не «закрыто»; см. `groups.js`: ставка XP
  зависит от размера набора символов и длины группы).
  Множитель за набор в `groups.js` — `sqrt(размер / 26)` с потолком 1, и
  это не произвольные числа (v2.33): делитель 26 = полный латинский
  алфавит, иначе маленький самодельный набор даёт ту же ставку, что и
  полный (был делитель 15 — реальная лазейка); корень — чтобы честные
  промежуточные наборы вроде «Цифры» (10) не штрафовались жёстко. Не
  «упрощай» обратно в линейную формулу. В `koch.js` формула намеренно
  ДРУГАЯ (старая, делитель 15): там набор задан уровнем, а не выбором
  человека, поэтому фармить им нельзя и ужесточение только било бы по
  мотивации на средних уровнях.
- **`database/schema.sql` — единственный источник истины по схеме БД.**
  Файлы миграций консолидированы в него и удалены в v2.28 (история — в
  git). Меняешь структуру или сид-данные: (1) правь `schema.sql` — свежие
  установки должны получать актуальную базу одним файлом; (2) в записи
  CHANGELOG.md приведи готовые ALTER/UPDATE/INSERT-команды для уже
  работающей базы — владелец живого сервера выполняет их вручную после
  `git pull` (автоматически initdb работает только на пустом volume);
  (3) новые файлы `migration_N.sql` больше НЕ создавай.
- **CLI-скрипты (`database/seed_callsigns.php` и подобные) — без стрелочных
  функций (`fn`) и без строгой типизации параметров.** На проде (SSH-консоль
  хостинга) может стоять более старая версия PHP, чем PHP-FPM самого сайта —
  уже ловили из-за этого `Call to undefined function fn()`.
- **Сигнальная линия и лампа — сквозной элемент дизайна** (`SignalLine`,
  `MorseLamp` из `assets/js/signal.js`). Новые режимы тренировки должны их
  подключать. Видимость сигнальной линии переключается через
  `wireSignalVisibilityToggle()` и общую настройку `DisplaySettings` — это
  сознательно (подсказка-читерство при тренировке слуха), не убирай
  переключатель.
- Пользователь развёртывает на VPS (FastPanel, PHP 8.4) через `git pull`.
  Продовые пути `config/`, `database/` и `includes/` закрыты `.htaccess` —
  не убирай эту защиту (там креды от БД, SQL-файлы и логика сессий).
- **Аккаунты — надстройка, не источник истины.** Прогресс пользователя
  (`Progress` в `assets/js/progress.js`) живёт в `localStorage`. Таблицы
  `users`/`user_stats` — только публичный слепок XP/серии для лидерборда
  на главной. Не переписывай логику так, будто сервер — единственный
  источник прогресса; localStorage должен продолжать работать полностью
  автономно даже без аккаунта.
- **Слияние прогресса при логине — только «вверх»** (`Progress.mergeFromServer`
  в `assets/js/progress.js`): числа — `Math.max`, множества
  (`learnedLetters`, `unlockedAchievements`) — union, даты — более поздняя.
  Никогда не выбирать меньшее и не перезаписывать одну сторону другой —
  raw-merge по максимуму гарантирует, что прогресс не теряется ни с одной
  стороны, поэтому диалоги подтверждения не нужны. Приватная синхронизация
  (`user_progress`, `api/push_progress.php`/`pull_progress.php`) и публичный
  лидерборд (`user_stats`, кнопка «Опубликовать») — две РАЗНЫЕ системы, не
  смешивать: синхронизация не требует подтверждённой почты и работает тихо,
  публикация в лидерборд — только вручную и только с подтверждённой почтой.
  «Сбросить весь прогресс» обязан удалять и серверную копию
  (`api/delete_progress.php`), иначе следующий логин откатит сброс.
- **Любая серверная проверка пароля — через общий счётчик блокировки**
  (`failed_login_attempts`/`locked_until`, лимит 5 попыток / 15 минут, как в
  `api/login.php`). Если добавляешь новый эндпоинт, принимающий пароль
  (сейчас это login и `update_account.php`), — он обязан и уважать активную
  блокировку, и инкрементировать счётчик при неверном пароле, иначе станет
  обходным путём для брутфорса мимо защиты логина.
- **Бонус задания дня требует точность ≥ 50 %**, не только совпадение
  параметров сессии — иначе бонус фармится прокликиванием пустых ответов
  (был реальный баг, закрыт в v2.26). Обычный XP за верные символы при
  низкой точности остаётся.
- **Почта — через Resend API** (`includes/resend_mailer.php`,
  `config/mail.php`), не через SMTP хостинга. Был реальный кейс: у
  `mail.r9old.ru` не настроен DKIM, а PTR общего IP не связан с доменом —
  Gmail тихо резал письма без bounce. Не откатывай на SMTP-подход без явной
  причины — уже проверено, что не работает надёжно на этом хостинге.
- **Никаких хардкоженных пользовательских строк** — интерфейс двуязычный
  (v2.49, бэклог-пункт 6 закрыт). Любой текст, который видит пользователь
  (PHP-шаблоны, JS, письма, ошибки API), — через `t('ключ')` из
  `includes/i18n.php` (в PHP) или глобальную `t()` из `assets/js/i18n.js` (в
  JS), а сам текст — в `lang/ru.php` И `lang/en.php` одновременно (ключи
  должны быть в обоих файлах, иначе фолбэк на ru тихо спрячет пропуск).
  Названия достижений переводятся отдельно, оверлеем по `code` в
  `api/achievements.php` (`ach_def.{code}.title/desc`) — сама БД
  (`achievements`) остаётся источником истины на русском, не переводи её
  напрямую. Слоговые мнемоники (`MORSE_MNEMONICS` в `morse-data.js`) —
  осознанное исключение: это русская фонетическая подсказка, не
  переводится, а просто отключается для английского интерфейса
  (`window.MW_LANG === 'en'`). В JS-файлах, где используется локальная
  переменная/параметр по имени `t`, — не давай ей это имя, если в той же
  области видимости также нужен глобальный `t()` (было по-настоящему
  затенение в `progress.js`, лови на код-ревью).
- **Кириллическая азбука Морзе — готова** (v2.51, бэклог-пункт 1 закрыт;
  см. README.md/README.ru.md, раздел «Как это устроено внутри»). Отдельная
  таблица CYRILLIC_CODE/CYRILLIC_TO_CHAR в morse-data.js, НЕ смешанная
  с латинской (коды намеренно совпадают с «похожими» латинскими буквами —
  общий реверс-словарь сломал бы декодирование ключом). Прогресс хранится
  в learnedLetters с префиксом RU_. letters_learned_count в progress.js
  считается строго по ALL_LEARNABLE (латиница+цифры) — не убирай этот
  фильтр, иначе ачивка «Полный алфавит» будет засчитываться раньше времени
  от суммы латиницы+кириллицы. XP: одинаковая ставка для латиницы и
  кириллицы везде — 25 за отправку ключом, 1 за приём на слух (v2.51.1
  ставил кириллице бонус +2 в приёме на слух, но он путал: одинаково
  выглядящие латинская и кириллическая «M» давали разный XP — убран в
  v2.51.7). Не вводи разницу по алфавиту в ставках без явной просьбы
  владельца. Любой фидбек-текст с суммой XP
  обязан подставлять сумму через плейсхолдер в t(), а не хардкодить число
  в lang/*.php — однажды из-за этого разошлись реальная и отображаемая
  сумма. Кириллица есть только в «Буквах» — в «Метод Коха»/«Группы» её нет
  и не планируется (см. известные ограничения в README). Две ачивки на
  кириллицу: `cyrillic_learned_count` (отправка ключом, learnedLetters) и
  `cyrillic_recognized_count` (приём на слух, отдельный счётчик
  `recognizedUniqueLetters` + `Progress.markRecognizedUnique()`, v2.51.8) —
  не путай их, это разные счётчики за разные режимы.

## Открытые задачи (бэклог — согласован с владельцем, порядок ≈ приоритет)

Браться по возможности, сверху вниз. Перед реализацией перечитай
«Обязательные правила» выше — особенно про XP, AudioContext и schema.sql.

1. **Мини-игра в стиле Марио** (владелец очень ждёт): платформер-раннер,
   где препятствия проходятся выбором правильного символа на слух и/или
   удержанием правильного ритма ключа (точка — короткий прыжок, тире —
   длинный?). Отдельный пункт меню (место в таббаре освобождено в v2.24).
   Механику согласовать с владельцем перед реализацией — начать с
   короткого описания вариантов геймплея.
2. ~~**Оценка ритма ключа**~~ — реализовано в v2.53 (сверка с владельцем
   2026-07-29): третий подрежим в «Буквах» наравне с «Отправка ключом» и
   «Приём на слух», показывает отклонение длительностей от идеала
   (точка:тире:пауза-внутри-буквы = 1:3:1 — честная телеграфная классика;
   в старой версии этого пункта ошибочно стояло 1:3:1,7 без обоснования,
   поправлено). Скорость (wpm) свободно регулируется — идеал пересчитывается
   относительно неё, это осознанно поданная фишка (см. `learn.rhythm_intro`
   в `lang/*.php`). **XP — по той же анти-фарм схеме, что и "Отправка
   ключом"** (после теста владельцем на локалке переделано с исходного
   "линейно от точности за каждую попытку" — фармилось спамом простого
   символа): +25 XP разово, когда набрано 5 точных повторов подряд (буква
   верная И точность ≥80%), см. `assets/js/learn.js` →
   `handleRhythmLetter`/`REQUIRED_RHYTHM_STREAK`. Отдельный список
   `Progress.rhythmMasteredLetters` (не путать с `learnedLetters` —
   разные статусы одной и той же буквы, на плитках разные бейджи).
   Наработки (замер длительностей через `TelegraphKey.onPress`/`onSymbol`
   в `input.js`) пригодятся и для мини-игры (см. ниже).
3. **(Дальний прицел) Полноценное Android-приложение.** НЕ PWA — владелец
   явно против («выглядит неполноценно»). Отдельный большой проект.
4. **(Исследование) Подключение реального телеграфного ключа.** Владельцу
   интересно на будущее. Реалистичные пути: (а) самый простой — адаптер
   на Arduino/Pro Micro, эмулирующий клавиатуру (замыкание ключа =
   нажатие пробела; наш ввод в `input.js` уже слушает пробел — заработает
   без правок кода); (б) Web Serial API для самодельных адаптеров;
   (в) микрофонный вход + детекция тона через Web Audio (ключ радиостанции
   с сайдтоном). Начать с (а) — возможно, достаточно просто написать
   инструкцию-страничку, как собрать адаптер.
5. **Адаптивный декодер приёма на слух — свой, не сторонняя библиотека.**
   Идея владельца — по мотивам morse-pro (`scp93ch/morse-pro` на GitHub,
   класс `MorseDecoderAdaptive`): декодер, который по таймстемпам
   сигнал/пауза сам подстраивается под реальную скорость передачи
   (скользящее окно оценки длительности «точки» по последним N сигналам,
   пороги точка/тире/паузы пересчитываются от этой оценки) — вместо сверки
   с заранее выбранным wpm, как сейчас. **НЕ копировать код morse-pro** —
   она под EUPL-1.2 (не MIT), и модификации, которые нам всё равно придётся
   вносить (адаптация под свой формат `TelegraphKey`/`input.js`), эта
   лицензия требует публиковать открыто; MorseWave и так MIT и публичный,
   но юридически и стилистически чище написать оценщик длительностей с
   нуля под наш vanilla-подход (без ES6-классов), взяв только идею
   алгоритма, а не файлы. Пригодится сразу для двух вещей: (а) реальный
   приём с телеграфного ключа/микрофона без привязки к выбранному wpm,
   (б) синергия с п.2 «Оценка ритма ключа» — тот же скользящий оценщик
   длительностей переиспользуется для сравнения ритма с идеалом.

Отклонено владельцем (не предлагать повторно без его инициативы):
- QSO-симулятор — уже есть отдельный проект Morse Walker (https://morse.r9o.ru),
  ссылка на него стоит на главной пятым шагом «Пути новичка» (v2.34).
  Авторство: проект W6NYC (https://github.com/sc0tfree/morsewalker),
  русская редакция — владелец, R9OGL (https://github.com/loloka/morsewalker):
  двуязычный интерфейс, режим RDA с 85 регионами, генератор российских
  позывных. Если правишь этот блок — атрибуцию не убирай.
- PWA — владелец не любит, ждём полноценный Android (п.4).
- График XP по дням — «лишнее нагромождение».
- Недельный лидерборд — пока не нужен, вечная таблица мотивирует.

## Прежде чем коммитить

- Проверь синтаксис изменённых `.php` файлов (`php -l путь/к/файлу.php`,
  доступно внутри контейнера: `docker compose exec app php -l ...`).
- Добавь короткую запись в CHANGELOG.md (свежие записи сверху) — так
  следующая сессия (и человеческая, и ИИ) видит, что менялось.
