# MorseWave — контекст для Claude Code

Тренажёр азбуки Морзе. PHP (без фреймворка) + MySQL (PDO) + ванильный JS.
Живёт на https://morse.r9old.ru, репозиторий: https://github.com/loloka/morsewave

Этот файл — только то, что нужно знать *перед тем как писать код*. Держи его
компактным: он грузится в контекст целиком каждую сессию. Подробности — по
ссылкам, не сюда:

- архитектура и режимы — [README.md](README.md) (русский, основной) /
  [README.en.md](README.en.md) (синхронная копия);
- запуск, деплой, миграции, админка — [DEPLOY.md](DEPLOY.md);
- история — [CHANGELOG.md](CHANGELOG.md) (v2.49+) и
  [CHANGELOG-archive.md](CHANGELOG-archive.md) (старее, нужен редко).

Пометка «(v2.31)» у правила = запись в CHANGELOG с разбором конкретного бага.
Правило кажется странным — сначала прочитай её: почти каждое написано по
следам реальной поломки, а не из вкуса.

Интерфейс сайта двуязычный (ru/en, v2.49). README и этот файл двуязычны
отдельно и независимо от рантайм-интерфейса.

## Локальный запуск

```bash
docker compose up -d --build
```
Сайт: http://localhost:8080 · phpMyAdmin: http://localhost:8081 (root / morsewave_root)

MySQL-контейнер накатывает `database/schema.sql` (полная схема с сидами)
автоматически — но **только один раз**, на пустом volume. На уже существующей
базе изменения применяются вручную: phpMyAdmin или `docker compose exec db mysql ...`.

## Обязательные правила (не откатывать без явной просьбы владельца)

### Звук и управление тренировкой

- **Один `AudioContext` на весь сайт**: только `getSharedAudioContext()` из
  `assets/js/audio.js`, никогда `new AudioContext()`. У браузеров лимит на
  живые контексты, новый на каждое воспроизведение вешал тренировку намертво.
  Все `await audio.play(...)` — в `try/catch/finally`, сбрасывающий флаг
  занятости (`isPlaying`/`recBusy`) в `finally`.
- **«Остановить» обязана останавливать по-настоящему** (v2.31). Флага
  `running = false` мало: идущий `await audio.play()` доигрывает символ, а
  отложенный `setTimeout` всё равно срабатывает — на повторном «Начать»
  цепочки идут параллельно и звук накладывается сам на себя. Шаблон в
  `learn.js`/`groups.js`: токен запуска (`recSessionId`/`abbrevSessionId`),
  сверяемый старой цепочкой в `finally` и `onSymbol`, плюс общая функция
  (`haltRecognize()`/`haltAbbrev()`) — гасит `MorseAudio.stop()`, снимает
  `clearTimeout`, чистит лампу и линию. Её же звать при уходе со вкладки.
- **wpm-контролы — везде `<input type="range">` с шагом 1**, не `<select>`
  с пресетами. Осознанное решение владельца.
- **Сигнальная линия и лампа — сквозной элемент дизайна** (`SignalLine`,
  `MorseLamp` из `assets/js/signal.js`), новые режимы обязаны их подключать.
  Видимость — через `wireSignalVisibilityToggle()` и `DisplaySettings`;
  переключатель не убирай, видимая линия это читерство при тренировке слуха.

### XP и достижения

- **XP — всегда целые числа.** `Progress.addXp()` округляет `Math.round`.
  Дробный множитель — округляй ДО вызова `addXp`, не после: сложение дробных
  даёт `592.5000000000002` (было багом).
- **XP не должен фармиться** повторением тривиального действия; новый источник
  XP — сразу с защитой. Образцы: `learn.js` (XP только пока символ не
  «закрыт»), `groups.js` (ставка от размера набора и длины группы).
  Множитель набора в `groups.js` — `sqrt(размер / 26)` с потолком 1, числа не
  произвольные (v2.33): делитель 26 = полный латинский алфавит (при 15 была
  лазейка — крошечный самодельный набор давал ставку как полный), корень —
  чтобы честные наборы вроде «Цифр» (10) не штрафовались жёстко. Обратно в
  линейную формулу не «упрощай». В `koch.js` формула намеренно ДРУГАЯ (старая,
  делитель 15): набор задан уровнем, а не человеком, фармить нечем, а
  ужесточение било бы по мотивации.
- **Бонус задания дня требует точность ≥ 50 %**, не только совпадение
  параметров сессии — иначе фармится прокликиванием пустых ответов (v2.26).
  Обычный XP за верные символы при низкой точности остаётся.
- **Двигаешь счётчик под ачивку — проверь, перепроверяет ли сама функция.**
  Большинство мутаторов `Progress` (`incrementStat`, `addXp`,
  `markRecognizedUnique`, `setKochLevel`, `markKochLevelEarned`,
  `completeDailyChallenge`, `markDailyActivity`) сами зовут
  `checkAchievements()` внутри — доп. вызов не нужен. Два исключения, где
  ОБЯЗАН позвать вызывающий код: `markLetterLearned()` и
  `markRhythmMastered()`. Ловилось дважды именно на исключениях —
  «Вторжение» (v2.55) и «Ритм ключа» (v2.56, см. CHANGELOG). Аудит
  2026-08-01 других пропусков не нашёл — если добавляешь новый мутатор,
  не полагайся на этот список по памяти, смотри код самой функции.
- **Ачивки, считающие буквы, фильтруют набор по `ALL_LEARNABLE`** (латиница +
  цифры), иначе сумма с кириллицей засчитает «Полный алфавит» раньше времени.

### Данные, аккаунты, безопасность

- **`database/schema.sql` — единственный источник истины по схеме БД.**
  Миграции консолидированы в него и удалены в v2.28. Меняешь структуру или
  сиды: (1) правь `schema.sql`; (2) в запись CHANGELOG положи готовые
  ALTER/UPDATE/INSERT для живой базы — владелец выполняет их руками после
  `git pull`; (3) новые `migration_N.sql` НЕ создавай.
- **Аккаунты — надстройка, не источник истины.** Прогресс живёт в
  `localStorage` (`Progress` в `assets/js/progress.js`); `users`/`user_stats` —
  лишь публичный слепок XP/серии для лидерборда. localStorage обязан работать
  полностью автономно, без аккаунта.
- **Слияние прогресса при логине — только «вверх»** (`Progress.mergeFromServer`):
  числа `Math.max`, множества (`learnedLetters`, `unlockedAchievements`) union,
  даты — более поздняя. Никогда не брать меньшее и не перезаписывать одну
  сторону другой — потому и диалоги подтверждения не нужны.
- **Синхронизация и лидерборд — РАЗНЫЕ системы, не смешивать.** Приватная
  синхронизация (`user_progress`, `api/push_progress.php`/`pull_progress.php`)
  идёт тихо и без подтверждённой почты; публикация в лидерборд (`user_stats`,
  кнопка «Опубликовать») — только вручную и только с подтверждённой. «Сбросить
  весь прогресс» обязан удалять и серверную копию (`api/delete_progress.php`),
  иначе следующий логин откатит сброс.
- **Любая серверная проверка пароля — через общий счётчик блокировки**
  (`failed_login_attempts`/`locked_until`, 5 попыток / 15 минут, как в
  `api/login.php`; сейчас пароль принимают login и `update_account.php`).
  Новый такой эндпоинт обязан и уважать активную блокировку, и
  инкрементировать счётчик — иначе он обход защиты логина брутфорсом.
- **Почта — через Resend API** (`includes/resend_mailer.php`,
  `config/mail.php`), не через SMTP хостинга: у `mail.r9old.ru` нет DKIM, а
  PTR общего IP не связан с доменом — Gmail тихо резал письма без bounce.
  На SMTP не откатывай, уже проверено.
- **Продовые `config/`, `database/`, `includes/` закрыты `.htaccess`** —
  защиту не убирай (креды БД, SQL, логика сессий). Деплой — VPS (FastPanel,
  PHP 8.4) через `git pull`.
- **CLI-скрипты (`database/seed_callsigns.php` и подобные) — без стрелочных
  функций (`fn`) и без строгой типизации параметров**: в SSH-консоли хостинга
  PHP старее, чем PHP-FPM сайта, уже ловили `Call to undefined function fn()`.

### Тексты и языки

- **Никаких хардкоженных пользовательских строк** (v2.49). Любой видимый текст
  (PHP-шаблоны, JS, письма, ошибки API) — через `t('ключ')` из
  `includes/i18n.php` или глобальной `t()` из `assets/js/i18n.js`, а сам текст
  — в `lang/ru.php` И `lang/en.php` сразу: ключ должен быть в обоих, иначе
  фолбэк на ru тихо спрячет пропуск.
- **Сумма XP в тексте — только плейсхолдером в `t()`**, не числом в
  `lang/*.php`: однажды реальная и отображаемая суммы разошлись.
- **Названия достижений переводятся оверлеем** по `code` в
  `api/achievements.php` (`ach_def.{code}.title/desc`); таблица `achievements`
  — источник истины на русском, её напрямую не переводи.
- **Мнемоники** (`MORSE_MNEMONICS` в `morse-data.js`) — осознанное исключение:
  русская фонетическая подсказка не переводится, а отключается при
  `window.MW_LANG === 'en'`.
- В JS не называй локальную переменную `t`, если в той же области нужен
  глобальный `t()` — было реальное затенение в `progress.js`.

### Кириллица (v2.51)

- **Отдельные `CYRILLIC_CODE`/`CYRILLIC_TO_CHAR` в `morse-data.js`, НЕ
  смешанные с латинскими**: коды намеренно совпадают с «похожими» латинскими
  буквами, общий реверс-словарь сломал бы декодирование ключом.
- Прогресс — в `learnedLetters` с префиксом `RU_`; `letters_learned_count`
  считается строго по `ALL_LEARNABLE`, фильтр не убирай.
- **XP одинаковый для латиницы и кириллицы**: 25 за отправку ключом, 1 за
  приём на слух. Бонус +2 кириллице в приёме был в v2.51.1 и убран в v2.51.7 —
  одинаково выглядящие латинская и кириллическая «M» давали разный XP.
  Разницу по алфавиту не вводи без явной просьбы владельца.
- Кириллица только в «Буквах»; в «Методе Коха» и «Группах» её нет и не будет.
- Две РАЗНЫЕ ачивки: `cyrillic_learned_count` (отправка ключом, по
  `learnedLetters`) и `cyrillic_recognized_count` (приём на слух, счётчик
  `recognizedUniqueLetters` + `Progress.markRecognizedUnique()`, v2.51.8).

  Замер длительностей (`TelegraphKey.onPress`/`onSymbol` в `input.js`)
  переиспользуется в п.3 бэклога.

## Открытые задачи (бэклог — согласован с владельцем, порядок ≈ приоритет)

Браться сверху вниз. Перед реализацией перечитай «Обязательные правила» —
особенно про XP, AudioContext и schema.sql.

1. **(Дальний прицел) Полноценное Android-приложение.** НЕ PWA — владелец
   явно против («выглядит неполноценно»). Отдельный большой проект.
2. **(Исследование) Подключение реального телеграфного ключа.** Пути:
   (а) адаптер на Arduino/Pro Micro, эмулирующий клавиатуру (замыкание ключа =
   пробел, а `input.js` пробел уже слушает — заработает без правок кода);
   (б) Web Serial API для самодельных адаптеров; (в) микрофонный вход +
   детекция тона через Web Audio. Начинать с (а) — возможно, хватит
   страницы-инструкции, как собрать адаптер.
3. **Адаптивный декодер приёма на слух — свой, не сторонняя библиотека.**
   Идея как в morse-pro (`scp93ch/morse-pro`, `MorseDecoderAdaptive`):
   скользящее окно оценки длительности «точки» по последним N сигналам, от неё
   пересчитываются пороги точка/тире/пауза — вместо сверки с заранее выбранным
   wpm. **Код morse-pro НЕ копировать**: она под EUPL-1.2 (не MIT), адаптация
   под наш `TelegraphKey`/`input.js` неизбежна, а эта лицензия требует
   публиковать модификации открыто. Чище написать оценщик с нуля под наш
   vanilla-подход (без ES6-классов), взяв идею, а не файлы. Даст два
   выигрыша: приём с ключа/микрофона без привязки к wpm, и тот же оценщик
   переиспользуется в «Ритме ключа».

Отклонено владельцем (не предлагать повторно без его инициативы):

- QSO-симулятор — есть отдельный проект Morse Walker (https://morse.r9o.ru),
  ссылка на главной пятым шагом «Пути новичка» (v2.34). Авторство: проект
  W6NYC (https://github.com/sc0tfree/morsewalker), русская редакция —
  владелец, R9OGL (https://github.com/loloka/morsewalker). Атрибуцию не убирай.
- PWA — владелец не любит, ждём полноценный Android (п.1).
- График XP по дням — «лишнее нагромождение».
- Недельный лидерборд — вечная таблица мотивирует лучше.

## Прежде чем коммитить

- Проверь синтаксис изменённых `.php` (`php -l путь/к/файлу.php`, внутри
  контейнера: `docker compose exec app php -l ...`).
- Добавь короткую запись в CHANGELOG.md, свежие записи сверху.
  **Не читай CHANGELOG.md целиком ради этого** — файл большой, и его чтение
  под каждую правку впустую съедает контекст сессии. Хватит первых ~10 строк
  (шапка), новый блок вставляй перед самым верхним `## v...`:

  ```bash
  { head -8 CHANGELOG.md; cat new_entry.md; tail -n +9 CHANGELOG.md; } > tmp && mv tmp CHANGELOG.md
  ```

  В `CHANGELOG-archive.md` лезь только за исторической деталью.
